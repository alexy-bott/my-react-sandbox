# Работа с учебными задачами

После fork или clone проект уже готов к решению задач: создавать рабочую папку вручную не нужно.

## Первый запуск

```bash
pnpm install
pnpm dev
```

Выбери задачу в приложении, открой её `task.md` и работай в `attempts/current/`.

## Структура задачи

```text
src/tasks/<task-id>/
├── task.md
├── active.ts
├── starter/
│   └── полный исходный набор файлов
└── attempts/
    ├── README.md
    └── current/
        └── текущая рабочая копия
```

- `task.md` — условие задачи.
- `starter/` — неизменяемое исходное состояние задачи.
- `attempts/current/` — место, где пользователь сейчас решает задачу.
- `active.ts` — стабильная точка входа, запускающая компонент из `current`.
- `attempts/YYYY-MM-DD/` — сохранённые предыдущие прохождения.

На первом запуске `current` уже существует и совпадает со `starter`.

## Текущая попытка

Изменяй только файлы внутри `attempts/current/`. Не редактируй `starter/`: он нужен для сброса задачи и повторного прохождения.

Многофайловая задача хранит в `current` полный набор своих TSX, CSS, данных и остальных изменяемых файлов.

## Завершение и повторное прохождение

1. После завершения сохрани полный `current` как `attempts/YYYY-MM-DD/`.
2. При необходимости добавь в сохранённую попытку `solution.md` с описанием решения.
3. Восстанови новый `current` полным содержимым `starter`.
4. Продолжай работу в новом `current`.

Если за один день нужно сохранить несколько прохождений, добавь суффикс, например `2026-08-20-2` или `2026-08-20-resize-observer`.

## Ветка владельца

Владелец исходного репозитория ведёт личную работу в ветке `practice`, чтобы `main` сохранял чистые `current`, изначально совпадающие со `starter`. Для пользователей fork или clone ветка `practice` не обязательна — работать можно в своей текущей ветке.
