# Fetch-компонент: флоу реализации

## Задача

Создать React-компонент, который делает запрос к API, получает данные и отрисовывает список.

## Основной флоу

* Создаём компонент.
* Описываем тип данных, если используем TypeScript.
* Создаём состояние для данных.
* Создаём состояние для загрузки.
* Создаём состояние для ошибки.
* Выносим URL в отдельную константу.
* Выносим функцию запроса отдельно от компонента.
* Внутри функции запроса делаем `fetch`.
* Проверяем успешность ответа через `response.ok`.
* Если ответ неуспешный — выбрасываем ошибку.
* Если ответ успешный — читаем тело ответа через `response.json()`.
* Возвращаем данные из функции запроса.

## Флоу внутри компонента

* Используем `useEffect`, чтобы выполнить запрос после первого рендера.
* Внутри `useEffect` создаём функцию загрузки данных.
* Перед запросом включаем состояние загрузки.
* Перед запросом очищаем старую ошибку.
* Вызываем функцию получения данных.
* После успешного ответа сохраняем данные в state.
* В `catch` сохраняем ошибку в state.
* В `finally` выключаем состояние загрузки.

## Отрисовка

* Если идёт загрузка — показываем loader.
* Если есть ошибка — показываем сообщение об ошибке.
* Если данных нет — можно показать пустое состояние.
* Если данные есть — отрисовываем список через `map`.
* Для элементов списка обязательно указываем `key`.

## TypeScript-моменты

* Для массива данных указываем тип в `useState`.
* Для функции запроса указываем возвращаемый тип.
* Для `AbortController` используем тип `AbortSignal`.
* Ошибка в `catch` имеет тип `unknown`, поэтому перед обращением к `message` нужно проверить, что это `Error`.

## AbortController

* Создаём `AbortController` внутри `useEffect`.
* Передаём `controller.signal` в функцию запроса.
* В cleanup-функции вызываем отмену запроса.
* Ошибку `AbortError` не показываем пользователю, потому что это штатная отмена запроса.

## Как объяснить на собесе

* Компонент хранит три состояния: данные, загрузку и ошибку.
* Запрос выполняется в `useEffect`, чтобы не запускать его на каждый рендер.
* `fetch` возвращает объект `Response`, а не готовые данные.
* `response.ok` нужен, потому что `fetch` не падает автоматически на статусы 404/500.
* `response.json()` читает body ответа и превращает JSON в обычные JS-данные.
* После `setState` компонент перерендеривается и показывает полученные данные.
* API-логику лучше вынести отдельно, чтобы компонент отвечал только за UI и состояние.
* `AbortController` нужен, чтобы отменить запрос при размонтировании компонента.
