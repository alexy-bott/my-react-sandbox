# Первый отложенный вызов

Открой [timer.js](./timer.js). В терминале из корня проекта выполни:

```sh
node src/tasks/js-basics/timeout-basics/timer.js
```

Обе строки выводятся сразу. Измени код так, чтобы «Старт» появлялся сразу, а «Можно запускать поиск» — один раз примерно через секунду. Повтори команду и сравни результат.

## Следующий шаг с функцией и браузером

Открой [scheduleMessage.ts](./scheduleMessage.ts). Реализуй однократный вызов переданной функции через 1000 мс. В браузерном каталоге открой «Первый отложенный вызов» и разверни проверочный экран.

## Шаг 2 — вернуть id таймера

После проверки первого шага продолжай в [scheduleMessage.ts](./scheduleMessage.ts). Сохрани отложенный вызов через 1000 мс и сделай так, чтобы scheduleMessage возвращала id созданного таймера. Это понадобится вызывающему коду для отмены сообщения следующим шагом.

Критерий: при вызове `const timerId = scheduleMessage(showMessage)` переменная timerId получает id таймера, а не undefined. Интерфейс пока работает так же, как на первом шаге. Компонент и starter не меняй. После изменения функции напиши «проверь».

## Рабочая попытка

Решение пиши в рабочих файлах рядом с этим условием. `starter/` сохраняет исходную заготовку. Чтобы начать заново, сначала сохрани свою попытку, затем восстанови все три файла из [starter/](./starter/). После реализации и запуска напиши «проверь» для ревью локальных файлов.

После самостоятельной проверки сравни с ответом для [консоли](./solution/timer.js) или [функции](./solution/scheduleMessage.ts).
