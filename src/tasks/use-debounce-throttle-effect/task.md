# Эффекты с debounce и throttle

## Цель

Самостоятельно реализовать два хука: `useDebounceEffect` и `useThrottleEffect`.
Подготовленный UI предназначен только для проверки твоего кода на каждом этапе.

## Где писать код

**Редактируй только `attempts/current/useTimedEffects.ts`.**
В этом файле находятся две заготовки с комментариями `TODO`.

`attempts/current/demo/UseDebounceThrottleEffectTask.tsx` — готовый демонстрационный интерфейс. Не нужно переписывать его или менять JSX: он уже подключён к твоим хукам.

`starter/` — эталонное начальное состояние. Его не редактируй; используй для сброса текущей попытки.

## Контракт

Оба хука принимают `effect`, массив зависимостей `deps` и `delay` в миллисекундах.

- `useDebounceEffect` запускает эффект только после паузы длительностью `delay` с момента последнего изменения зависимостей.
- `useThrottleEffect` ограничивает частоту запуска эффекта: не чаще одного раза за `delay` миллисекунд.

## Этапы и проверка в UI

### Этап 1 — debounce

Реализуй `useDebounceEffect`. Запусти Sandbox и открой задачу.

1. В поле **Debounce** быстро введи несколько символов.
2. `Raw value` должно обновляться немедленно.
3. `Debounced value` должно обновиться после паузы **400 мс**; пока продолжается ввод, отложенный запуск должен переноситься.

### Этап 2 — throttle

Реализуй `useThrottleEffect`.

1. В поле **Throttle** последовательно вводи символы без длительных пауз.
2. `Raw value` должно меняться сразу.
3. `Throttled value` и сообщение `Throttled:` в консоли должны обновляться с ограничением частоты: **не чаще одного раза за 1000 мс**.

### Этап 3 — очистка

Проверь очистку отложенных запусков при изменении зависимостей и размонтировании компонента. Для размонтирования можно переключить активную задачу в Sandbox. Устаревшие запланированные эффекты не должны выполняться.

**Примечание:** в режиме разработки React `StrictMode` может дополнительно запускать setup и cleanup эффектов при первоначальном монтировании. Для оценки интервалов ориентируйся на изменения значений после монтирования.
