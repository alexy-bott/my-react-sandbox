# Эффекты с debounce и throttle

## Цель

Реализуй два хука: `useDebounceEffect` и `useThrottleEffect`. Готовый UI используется только для проверки твоего решения и не реализует алгоритмы за тебя.

## Где писать код

**Редактируй `attempts/current/useTimedEffects.ts`.** В нём находятся две заготовки с `TODO`.

`attempts/current/demo/UseDebounceThrottleEffectTask.tsx` — готовый стенд: инпуты, значения, счётчики и кнопка размонтирования. Изменять его не нужно. Он импортирует твои хуки.

`starter/` — эталонное начальное состояние для сброса. Его не редактируй.

## Контракт

Оба хука принимают `effect` (React `EffectCallback`), `deps` (React `DependencyList`) и `delay` в миллисекундах.

### `useDebounceEffect`

- При монтировании и изменении зависимостей планирует выполнение `effect` через `delay`.
- Если зависимости изменились до выполнения, старый запуск отменяется и отсчёт начинается заново.
- Если изменились только не связанные с `deps` состояния компонента, таймер не должен сбрасываться.

### `useThrottleEffect`

Реализуй стратегию **leading + trailing**:

- Первый запуск выполняется без ожидания полного интервала (в том числе при первом монтировании).
- Во время непрерывного изменения зависимостей эффект продолжает выполняться, но **не чаще одного раза за `delay`**.
- Если во время интервала были изменения, после окончания интервала выполнится эффект с **последним значением**. Промежуточные значения можно пропускать.
- После прекращения ввода последнее значение не должно теряться.
- Перерисовки из-за других состояний, не входящих в `deps`, не должны сами по себе вызывать повторные запуски.

Важно: при первоначальном монтировании throttle может запустить эффект с пустой строкой ещё до ввода текста. Поэтому первый запуск и начало интервала могут предшествовать первому символу.

### Очистка

Для обоих хуков обязательны две разные операции:

- Отменять **ожидающие таймеры** при изменении зависимостей и размонтировании.
- Если `effect` уже выполнялся и вернул cleanup-функцию, вызывать её при смене зависимостей или размонтировании. Не вызывать cleanup, если эффект ещё не был запущен.

## Этапы и проверка через UI

### Этап 1 — debounce (400 мс)

Вводи текст непрерывно, делая паузы меньше 400 мс. `Raw value` должно изменяться сразу, а `Debounced value` — только через 400 мс после последнего изменения. Затем введи ещё символ: отсчёт должен начаться заново.

### Этап 2 — throttle (1000 мс)

Печатай в поле **Throttle** непрерывно более 3 секунд. `Raw value` меняется сразу; `Throttled value` продолжает обновляться во время ввода. Наблюдай счётчик запусков и интервалы: соседние запуски не должны быть ближе 1000 мс. Прекрати ввод и проверь, что последнее введённое значение отобразилось после завершения ожидающего интервала.

Если просто заменить throttle на debounce, эта проверка **не пройдёт**: debounce не выполняет эффект во время непрерывного ввода.

### Этап 3 — очистка

Нажми **«Размонтировать стенд»**, пока ожидается отложенный запуск. После размонтирования новые запуски не должны происходить. В консоли можно наблюдать `Debounce effect cleanup:` и `Throttle effect cleanup:`, если соответствующие эффекты уже успели выполниться. Затем смонтируй стенд снова.

В режиме разработки React `StrictMode` дополнительно запускает setup/cleanup эффектов при первом монтировании. Поэтому оценивай частоту по обычной серии вводимых изменений, а не только по стартовым сообщениям консоли.

## Что тренируешь

- кастомные хуки и зависимости `useEffect`;
- debounce против throttle;
- устранение устаревших замыканий и лишних запусков;
- таймеры и cleanup.
