# Эффекты с debounce и throttle

## Цель

Реализуй два хука: `useDebounceEffect` и `useThrottleEffect`. Готовый UI помогает проверить каждый этап, но не содержит реализацию хуков.

## Где писать код

**Редактируй `attempts/current/useTimedEffects.ts`.** Там находятся обе функции с `TODO`.

`attempts/current/demo/UseDebounceThrottleEffectTask.tsx` — подготовленный интерфейс для проверки. Его изменять не нужно; он импортирует твою реализацию.

`starter/` — эталонная версия для сброса. Не редактируй её.

## Контракт

Оба хука принимают три аргумента: `effect` (функцию эффекта), `deps` (массив зависимостей React) и `delay` (миллисекунды).

- `useDebounceEffect`: при изменении зависимостей отменяет предыдущий ожидающий запуск и выполняет `effect` после паузы не короче `delay`.
- `useThrottleEffect`: ограничивает выполнение `effect` — не чаще одного раза за `delay`.

**О поведении throttle:** есть варианты `leading` (запуск в начале интервала), `trailing` (запуск ближе к концу интервала) и их сочетание. В этой задаче конкретный вариант не предписан. Реализуй выбранную стратегию, соблюдай интервал и укажи выбранную семантику коротким комментарием. Начальный запуск при монтировании также зависит от стратегии.

Оба хука принимают `EffectCallback`: если выполненный `effect` возвращает cleanup-функцию, она должна быть вызвана при смене зависимостей или размонтировании. Отложенные, ещё не начавшиеся запуски тоже следует отменять при cleanup.

## Этапы и проверка в UI

### Этап 1 — debounce

1. Реализуй `useDebounceEffect` и запусти Sandbox.
2. Быстро введи несколько символов в поле **Debounce**. `Raw value` должно изменяться сразу.
3. `Debounced value` должно обновиться после паузы **400 мс**. Пока ввод продолжается, ожидающий запуск отменяется и назначается заново.

### Этап 2 — throttle

1. Реализуй `useThrottleEffect`.
2. Печатай в поле **Throttle** без длинных пауз. `Raw value` должно меняться немедленно.
3. Следи за `Throttled value`, количеством запусков и временем между ними. После первоначального монтирования интервалы между последовательными выполнениями не должны быть меньше **1000 мс**.
4. Учитывай выбранную стратегию: она определяет, будет ли обработано последнее введённое значение.

### Этап 3 — очистка

В консоли можно наблюдать сообщения `Debounce effect cleanup:` и `Throttle effect cleanup:`. Убедись, что cleanup уже выполненного эффекта вызывается при смене зависимостей и размонтировании (например, при переключении задачи), а отменённые ожидающие запуски не выполняются.

В dev-режиме React `StrictMode` может выполнять дополнительный цикл setup/cleanup при первом монтировании. Это следует учитывать при анализе начальных сообщений и счётчиков.

## Что тренируешь

- таймеры, debounce и throttle;
- зависимости, cleanup и отмену отложенных действий.
