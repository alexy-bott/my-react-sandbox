# Реализовать хук useMinMatchMedia

**Рабочий файл:** [UseMinMatchMediaTask.tsx](./UseMinMatchMediaTask.tsx).

## Задание

Реализуй кастомный хук `useMinMatchMedia`.

Хук принимает объект с минимальными размерами viewport и опциональный callback. Он должен возвращать `boolean`: `true`, если текущие ширина и высота viewport не меньше переданных значений, иначе `false`.

При пересечении заданной границы после первоначального вычисления должен вызываться callback, если он передан. Речь о переходе общего результата проверки двух размеров, а не о каждом изменении размера окна. Если параметры запроса изменились, пересчитай результат для новых параметров; сам пересчёт не считается пересечением границы viewport.

```ts
interface MediaDimensions {
  width: number
  height: number
}
```

## Требования

- Учитывай одновременно минимальную ширину и минимальную высоту.
- Значение должно обновляться при изменении размеров viewport.
- Callback опционален; при последующих переходах вызывай его актуальную версию.
- Callback вызывается при переходе результата `false -> true` или `true -> false`.
- При первоначальном вычислении callback вызывать не нужно, в том числе при дополнительном цикле Strict Mode.
- После unmount не должны оставаться активные подписки. При смене параметров старую подписку нужно очистить.
- Размеры — конечные неотрицательные числа в CSS-пикселях. SSR и валидация некорректных размеров не входят в задачу.
- Не используй сторонние библиотеки.
- Можно пользоваться Google, но не AI.

## Что тренирую

- создание кастомных React-хуков
- browser API для media queries
- подписку и cleanup внешнего источника состояния
- TypeScript

## Как работать с задачей

Реализуй хук в рабочем файле; готовый интерфейс менять не нужно. До реализации песочница покажет сообщение вместо интерфейса.

Выбери «Реализовать хук useMinMatchMedia». В инструментах разработчика браузера выставь viewport 1024 × 768 и заново открой упражнение: результат true, пересечений 0. Измени размер на 1023 × 768 (false, 1), затем на 1100 × 767 (false, 1), затем на 1100 × 800 (true, 2). Изменение размера внутри той же области не вызывает callback. Уменьши высоту до 767 (false, 3). Для проверки необязательного callback временно замени вызов на `useMinMatchMedia({width: 1024, height: 768})` и убери состояние `changes` вместе со строкой вывода счётчика; результат должен по-прежнему обновляться. Затем восстанови интерфейс. Для проверки изменения параметров временно храни минимальную ширину в состоянии (начальное значение 1024) и добавь кнопку переключения между 1024 и 1200. При viewport 1100 × 800 изменение порога меняет результат, но не счётчик пересечений; дальнейшее изменение viewport должно проверяться уже относительно нового порога. После проверки восстанови исходный код потребителя. Для проверки актуальности callback временно замени `setChanges(count => count + 1)` на `setChanges(changes + 1)` и несколько раз пересекай границу: счётчик должен продолжать расти. Затем верни исходный callback.

Для проверки очистки временно выведи объект подписки (`MediaQueryList`, если используешь `matchMedia`) в консоль. В Chromium DevTools сохрани этот объект как глобальную переменную (например, `temp1`) и проверь `getEventListeners(temp1).change` до и после смены порога или ухода с упражнения. Старый обработчик должен исчезнуть. Если подписываешься на `resize`, аналогично проверь `getEventListeners(window).resize`. Убери временные изменения.

Для сохранения попытки скопируй рабочий файл в новую папку `attempts/YYYY-MM-DD/`. Для повторного прохождения восстанови его из [starter/UseMinMatchMediaTask.tsx](./starter/UseMinMatchMediaTask.tsx).
