# Code review и рефакторинг UsersPage

## Контекст

Представь, что `UsersPage.tsx` и `App.tsx` пришли в Pull Request. Код работает в базовом сценарии, но перед merge его нужно отревьюить и при необходимости отрефакторить как production-код.

Не требуется переписывать приложение с нуля. Ожидаются только изменения, которые действительно обоснованы найденными проблемами.

## Задание

Проведи code review обоих компонентов.

Для каждого существенного замечания сформулируй:

```text
проблема
→ почему это проблема
→ насколько она существенна
→ как исправить
```

После review покажи финальный вариант кода.

Обрати внимание на:

- React state и производные данные;
- корректность использования `useEffect`;
- `key` при рендеринге списка;
- использование `any` и типизацию данных;
- `fetch`, loading и обработку ошибок;
- целесообразность отдельного custom hook для загрузки пользователей;
- необходимость или отсутствие необходимости в `debounce`, `useMemo`, `useCallback`, `React.memo`;
- создание объектов и функций внутри компонента только там, где это действительно имеет значение.

Сохрани решение простым: не добавляй абстракции и оптимизации без причины.

## Дополнительный вопрос

Предположим, что поиск пользователей перенесли на API:

```text
GET /api/users?search=<query>
```

Пользователь может быстро вводить текст. Объясни, изменится ли решение и потребуется ли debounce.

## Критерий

После review код должен выглядеть так, чтобы PR можно было отправить в production.

## Как работать с задачей

Основные исходники — `attempts/current/UsersPage.tsx` и `attempts/current/App.tsx`.

`starter/` — чистая исходная версия. Используй её, если захочешь начать заново.
