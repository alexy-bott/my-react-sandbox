# Что произойдёт

При первом рендере список пуст, а Total Tasks показывает 1. Кнопка получает обработчик текущего рендера. Если ввести «Купить хлеб» и нажать Add Task, появится строка «Купить хлеб», поле очистится, а счётчик покажет 2.

Если теперь ввести «Позвонить» и нажать Enter, останется **одна пустая строка**, поле очистится, а счётчик покажет 2. Подписка на документ создана при первом рендере. Её обработчик помнит пустой текст, пустой массив и значение счётчика 1. Он заменяет весь текущий список массивом из одной записи с пустым текстом и id 1. Повторный Enter использует те же исходные значения.

## Как исправить

- Обернуть ввод и кнопку в форму и вызывать один обработчик через onSubmit с preventDefault. Тогда клик и Enter в поле используют текст текущего рендера. Исходный обработчик на document реагирует даже за пределами поля, остаётся после размонтирования и может дублироваться при повторной установке эффекта.
- При создании записи один раз назначить ей id и добавить её через функциональное обновление списка. Для Total Tasks выводить tasks.length. Сейчас taskCount одновременно служит следующим идентификатором и количеством строк, поэтому уже на пустом списке результат неверен.
- useCallback без списка зависимостей здесь не сохраняет ссылку между рендерами. Обычной функции для отправки формы достаточно.
